# 麦选· 今天吃什么决策助手

> 一句话定位：**麦选是一个基于麦当劳官方 MCP（mcd-mcp）的「今天吃什么」决策 Skill——问你人数、预算、位置、配送方式，用真实接口查门店/菜单/优惠/营养，替你选出能吃饱、又对味的一餐，价格全部经麦当劳算价接口验证，下单前必须你亲口确认。**

---

## 一、三种模式（可叠加）

| 模式 | 输入 | 输出 | 核心规则 |
|---|---|---|---|
| **预算模式** | 人数、总预算、城市、配送方式 | 2~3 套方案（最省锚点 + 最丰盛主推 + 平衡） | 每套用 `calculate-price` 验真实价，总价 ≤ 预算；**预算内东西更多者优先（铁律6：省钱不省量）** |
| **盲选模式** | "不知道吃啥" / 心情描述、城市、配送方式 | 果断推 1 主 + 2 备选，各带一句理由 | 先 `now-time-info` 判时段；**先吃饱再治愈（铁律5）**，甜品只作加成；说"换一个"就换且不重复 |
| **营养模式** | 热量上限、目标（高蛋白/低卡等）、人数、城市、配送方式 | 含热量/蛋白/价格的对比表 | 数据全部来自 `list-nutrition-foods`；匹配不上明说"该商品无营养数据"，不编造 |

三模式可叠加，例如"预算 50 + 热量别超 800 + 不知道吃啥"= 盲选 + 预算 + 营养同时生效。

**五条铁律（SKILL.md 里有完整版）**：① 价格只信 `calculate-price`（分÷100），不估算；② 营养对不上明说"无营养数据"；③ 下单/取消前必须完整复述门店、商品、金额、取餐方式，等你回"确认"才动；④ 人数/预算/位置/配送方式没齐先问，**配送方式必须在出方案前确认，禁止默认到店**；⑤ 食量优先于情绪——每个方案先是一顿能吃饱的完整餐，治愈/趣味作加成。

## 二、安装与使用

### 1. 前置条件（必装）
本机已配置麦当劳官方 MCP：`~/.workbuddy/mcp.json` 里 `mcpServers.mcd-mcp`，地址 `https://mcp.mcd.cn`，Bearer Token 鉴权。

麦当劳 MCP Server 开放平台官网：https://open.mcd.cn/mcp

### 2. 安装 Skill
把 `SKILL.md` + `references/` 整个复制到技能目录：
- **项目级**：`<你的项目>/.workbuddy/skills/麦选/`
- **用户级**：`~/.workbuddy/skills/麦选/`

装完重启会话即可，无需编译（纯指令文件 + 标准库脚本）。

### 3. 触发词
`麦选` / `今天吃什么` / `帮我选麦当劳` / `麦当劳点啥` / `预算点麦当劳` / `麦当劳热量` / `不知道吃啥点啥`

### 4. 辅助脚本（可选，scripts/ 目录）
纯 Python 标准库，无第三方依赖；Token 自动从 `~/.workbuddy/mcp.json` 读取，不硬编码。

```bash
# ① 任意 MCP 工具直调（真实数据在 structuredContent）
python3 scripts/mcd_client.py now-time-info
python3 scripts/mcd_client.py query-nearby-stores '{"searchType":2,"beType":1,"city":"深圳市","keyword":"麦当劳"}'

# ② 组合验价：对若干组合跑 calculate-price，输出实付（分→元）
python3 scripts/price_check.py

# ③ 预算+热量组合计算：菜单→营养匹配→验价→按"达标→件数多→蛋白高"排序
python3 scripts/combo_calc.py
```

## 四、真实对话示例（2026-10-22 实测，价格全部 `calculate-price` 验证）

### 示例 1：盲选 + 预算（2 人 60 元，到店）
**用户**："深圳，2 个人，预算 60，不知道吃啥"
麦选先确认配送方式（到店）→ 判时段（周四午后·午餐尾巴）→ 查深圳门店，默认最近（深圳湾文化广场餐厅 52 米）并列出全部门店供更换：

| 推荐 | 方案 | 真实价 |
|---|---|---|
| 🥇 主推 | 开心亲子双人餐 ×1 | **59.5 元** |
| 🥈 备选 | 麦香鸡套餐 ×2 | **56.0 元** |
| 🥉 备选 | "我就喜欢"鸡薯双全盒 ×2 + 心形薯饼 8 块 ×1 | **41.7 元** |

**实测彩蛋**：菜单上"全明星双人分享餐八件套"标价 49.9 看着超值，`calculate-price` 一算真实 **117.5 元**——那是"买麦金卡才有的价"。菜单价≠实付价，这就是铁律①存在的原因。

### 示例 2：盲选 · 治愈系（1 人，不卡预算，到店）
**用户**："今天加班好累，来点治愈的"
麦选确认 1 人 / 深圳 / 到店后出方案。第一版只推甜品（麦旋风 16.5 / 热巧克力 13.9 / 心形薯饼 9.9）被用户当场纠正"这不符合一个人的基本食量"——由此催生**铁律 5（食量优先于情绪）**。修正后：

| 推荐 | 方案 | 真实价 |
|---|---|---|
| 🥇 主推 | 麦香鸡套餐 + 蓝莓爆爆珠麦旋风 | **44.5 元** |
| 🥈 备选 | 麦辣鸡腿汉堡三件套 + 蓝莓麦旋风 | **43.4 元** |
| 🥉 备选 | 板烧鸡腿堡三件套 + 心形薯饼 5 块 | **50.0 元** |

### 示例 3：营养模式（≤700 大卡高蛋白，外送被拒→得来速）
**用户**："推荐一餐控制在 700 大卡以内，蛋白质尽量高"
用户选外送 → `query-nearby-stores(beType=2)` 被接口直接拒绝（`code 600046：仅支持到店和得来速`）→ 麦选如实告知，用户改选**得来速**（尚美科技大厦得来速餐厅，beType=5 / orderType=1 / 带 beCode）：

| 推荐 | 方案 | 蛋白 | 热量 | 真实价 |
|---|---|---|---|---|
| 🥇 主推 | 不素之霸双层牛堡 + 薄皮焦香 V 翅 | 45g | 685 kcal | **42.5 元** |
| 🥈 备选 | 双层吉士汉堡 + 薄皮焦香 V 翅 | 44g | 621 kcal | **39.0 元** |
| 🥉 备选 | 麦辣鸡腿汉堡 + 麦乐鸡(5块) | 36g | 698 kcal | **36.5 元** |

用户说"换别的搭配"→ 第二轮避开全部已推单品：板烧鸡腿堡+鸡翅+小杯玉米杯（38g/668kcal/51.5元）、芝士安格斯厚牛堡单堡（32g/696/31.5元）、那么大鸡排+鸡翅+大杯玉米杯（41g/696/42.0元）。

### 示例 4：预算 + 营养 + 套餐换选（1 人 50 元 ≤800 大卡，到店）
**用户**："预算 50，1 人，深圳，自提，热量别超 800，直接帮我选一个"
麦选先问"麦香鸡套餐里能换什么"，`query-meal-detail` 拆出套餐分层（主食固定 + 小食 7 选 1 + 饮料 24 选 1，每项带 `diffPrice`），再经 `items[].roundList` 把换选传进算价接口实测：

| 方案 | 换选/叠加 | 真实价 | 热量 | 判定 |
|---|---|---|---|---|
| ✅ **就选这个** | 麦香鸡套餐（小食换**小杯玉米杯 -1.5 元**、饮料换**无糖可口可乐 +0 元**）+ 麦辣鸡翅 2 块 | **41.5 元** | **646 kcal** | 4 件完整餐，双达标 |
| 备选 | 那么大鸡排 + 鸡翅 2 块 + 小杯玉米杯 | 42.0 元 | 662 kcal | 3 件，双达标，蛋白更高(39g) |
| ❌ 作废 | 麦香鸡套餐**默认**（中薯条+可乐中杯）+ 鸡翅 2 块 | 43.0 元 | **1029 kcal** | 超 800 上限 |

**两个实测纠错**（都写回了 SKILL.md）：① 换选不是都免费——大薯条 **+1.5 元**，真正免费的是无糖饮，小杯玉米杯反而**降 1.5 元**；② 曾估算"默认套餐+鸡翅 ≈760 大卡"，营养表逐项相加实为 **1029 大卡**，超限方案直接作废。

### 示例 5：券优化 + 下单/取消安全闭环
**用户**："领"（授权自动领券）→ `auto-bind-coupons` 真实将领麦麦省 3 张券放入卡包（11.9 元麦辣鸡腿堡 / 19.9 元王牌炸鸡任选 2 / 免费脆薯饼）→ 查本店券 → 券套餐带券码算价：11.9 与 19.9 两张**算出真实券价**（与券面价一致），脆汁鸡堡堡双人餐仍返回 0（只能下单确认）。按铁律 5，券套餐多为单品、不构成完整一餐，只作"极致省钱对照"单列，**不擅自把 42 元正餐换成 11.9 单堡**。

**下单闭环**（铁律③）：用户"选择主推方案，下单" → 麦选完整复述（门店/地址/商品/44.5 元/取餐柜）→ 用户回"确认" → `create-order` 成功，订单号 `1030643390000808586746426954`，15 分钟支付时限，**支付仅支持麦当劳 APP 扫码**（微信/支付宝不可用，用户实测确认）→ 用户"确认取消" → `cancel-order` 成功（`cancelResult=true`）。

## 六、已知限制（全部实测交底，不装支持）

1. **外送不可用**：`query-nearby-stores(beType=2)` 被接口拒绝（`600046 仅支持到店和得来速`），遇到外送需求须如实告知并改到店/得来速。
2. **支付仅麦当劳 APP 扫码**：`create-order` 只返回 `payH5Url`，微信/支付宝均不支持（用户 2026-10-22 实测确认）。
3. **券是"券套餐"不是满减券**：每张券绑定特定商品；特价单品类券套餐能算出真实券价，套餐类返回 `price=0`，只能下单时确认，绝不拿 0 或猜测值冒充实付。
4. **麦金卡假低价**：菜单标"随单购麦金卡"的低价不是实付价，必须 `calculate-price` 验。
5. **营养表无套餐条目**且名称带后缀（如"麦辣鸡翅-2块""小杯玉米杯"），需模糊匹配；匹配不上标"该商品无营养数据"。
6. `query-order`（查订单状态）未实测，未纳入流程。
